# 短剧行业数据看板 - 改进路线图

当前基线：v1.7.13，Kimi/Moonshot 负责联网搜索，DeepSeek 负责 JSON 推理，GitHub Actions 定时生成静态看板数据。

## 当前稳定能力

- GitHub Actions 每日北京时间 9:00 自动执行 `src/run_github.py`。
- 前端读取 `assets/data/latest.json`，支持历史数据。
- 剧集榜单目标为 TOP20。
- 前端“榜单 TOP20”已有代码层门禁：少于 20 条会补齐到 20 条，补齐失败则拒绝覆盖数据文件。
- 演员榜为女频 TOP10 + 男频 TOP10。
- 行业快讯最多 6 条，要求来源真实可追溯；数据不足时宁缺毋滥。
- 行业快讯摘要采用 150-200 字四段式结构化文本，包含“事件核心”“数据支撑”“商业洞察”“决策价值”，前端以三列卡片网格展示并保留原文链接。
- 搜索关键词使用动态日期，避免把往年数据当作今日数据。

## 主要风险

| 优先级 | 风险 | 表现 | 建议 |
|---|---|---|---|
| P0 | 数据真实性波动 | 搜索结果可能混入非当日或非短剧内容 | 增加质量门禁和来源校验 |
| P0 | 演员补全不稳定 | 搜索失败时容易出现空值或泛化推理 | 保留多轮搜索，并记录来源或置信度 |
| P1 | 题材分布偏粗 | `genre` 为空或落入“其他” | 在 `enrich_node` 中使用标准题材枚举 |
| P1 | 宏观数据格式不统一 | 字符串、数字、对象混用 | 输出前统一格式化 |

## 建议改进方向

### 近期变更记录

- 2026-06-12：优化 Tier 1 初始榜单抓取策略。`search_node` 的 Kimi 联网搜索提示词加入动态年月锚点，强制优先检索近 3-7 天日榜、周榜、实时热榜和带有“今日/最新/近7天”的关键词；明确过滤《我在八零年代当后妈》《无双》等历史累计总榜老剧，并要求播放量/热度优先采用单日新增、近期热度或实时热度指标。
- 2026-06-12：升级“每日行业快讯”深度摘要提示词。`news_node` 强制 `content` 输出 150-200 字四段式内容，依次覆盖 `【事件核心】`、`【数据支撑】`、`【商业洞察】`、`【决策价值】`，并要求 JSON 字符串内使用 `\n` 转义换行，降低结构化解析风险。
- 2026-06-12：重构“每日行业快讯”模块。`news_node` 的 LLM 提取提示词改为强制基于真实搜索结果生成，`source_url` 必须来自搜索结果中的真实 URL；前端 `assets/index.html` 将快讯区改为单列垂直列表、透明背景、细分隔线，并保留极简“原文链接 ->”按钮。

### 1. 数据质量门禁

在 `push_node` 前增加 `quality_gate_node` 或等价校验逻辑：

- 检查 `rankings` 数量是否达到最低阈值；当前 TOP20 展示至少需要 20 条。
- 检查 `rank/title/views/platform` 是否完整。
- 检查 `views_num` 是否为合理正数。
- 检查演员是否命中明显非短剧或传统影视明星高风险名单。
- 检查 `error_message` 是否包含 API 鉴权、限流或解析失败。
- 质量过低时避免覆盖正常页面，或在页面明显提示数据异常。

### 2. 来源与置信度

给关键字段补充可选来源信息：

- 榜单来源 URL。
- 演员、厂牌、集数字段的搜索来源。
- 行业快讯原文链接。
- AI 推理字段的置信度或说明。

### 3. 题材标准化

建议题材枚举：

```text
都市甜宠、都市逆袭、重生复仇、古装权谋、年代情感、战神赘婿、玄幻脑洞、悬疑推理、AI短剧、其他
```

`enrich_node` 应强制输出标准题材，并把 `core_trope` 控制在 2-3 个核心爽点标签。

### 4. Dashboard 数据质量提示

前端已经能显示基础错误信息，后续可升级为结构化模块：

- 本次更新时间。
- 数据质量分数。
- 数据源数量。
- 节点错误信息折叠展示。
- 今日数据不足时的降级说明。

## 当前不建议做

- 不要把更多数据写死进 `assets/index.html`。
- 不要用大段 mock 数据修补榜单。
- 不要只依赖 prompt 约束数据质量，应增加代码层校验。
- 不要继续新增大型历史总结类 Markdown；长期计划集中更新本文件。
