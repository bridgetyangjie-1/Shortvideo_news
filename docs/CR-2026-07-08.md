## 1. 背景

2026-07-08 以**短剧行业数据分析师**视角对全站代码与 `latest.json`（2026-07-07）进行 Review，发现系统「板块齐全、工程完整」，但**数据可信度**不足以支撑投流/选品决策。核心问题：

| 现象 | 影响 |
|------|------|
| 榜单后半段出现「李十三」「王十四」等编号式演员名 | 演员热力榜误导业务方 |
| 厂牌为「蓝海影视工作室」等模板化幻觉 | 供应链分析不可用 |
| 快讯含 `example.com`、虚构剧目《都市奇缘》 | 行业情报不可信 |
| `views_num` 实为周榜热播指数却被当作播放量 | 指标口径混淆 |
| `quality_score: 100` 与 anomalies/alerts 矛盾 | 质量门禁失去公信力 |
| 20/20 部 `series_id` 为空 | 红果详情爬虫链路断裂 |
| 标签「爱情/都市爱情/逆袭」重复且男女频未分列 | 题材风向标粗糙 |
| 行业 KPI 来自静态种子，无大盘消耗 | 缺少投流核心指标 |

## 2. P0 已解决问题（数据质量止血）

### 2.1 拦截幻觉演员名 / 厂牌

**根因：** `json_refiner.py` prompt 要求「严禁填未知、从名单猜测」；`fallback.py` 用候选演员池凑数；质量门禁不识别编号式假名。

**修复：**

| 改动 | 说明 |
|------|------|
| `src/utils/data_quality.py`（新增） | `is_hallucinated_actor_name`、`is_suspicious_studio_name`、`sanitize_production_house` |
| `src/tools/actor_name_utils.py` | 扩展识别「李十三」「王十四」等编号式占位名 |
| `json_refiner.py` + `config/enrich_llm_cfg.json` | 无信源留空，禁止编造演员/厂牌 |
| `enrich/fallback.py` | 删除候选池凑数，仅清洗占位名 |
| `quality_gate_node` | 新增 `ranking_hallucination` **硬性门禁**（可疑演员 >2 或可疑厂牌 >3 → blocked） |
| `actor_ranking_node` | 幻觉演员不入热力榜 |

### 2.2 快讯 URL / 内容真实性

| 改动 | 说明 |
|------|------|
| `news_node` | 拦截 `example.com`、Google/Baidu 搜索页；`insight` 为空时从 content「商业洞察」段自动提取 |
| `quality_gate_node` | 新增 `daily_news_url_trust`、`daily_news_insight` 检查；告警按条数扣分 |

### 2.3 热度字段概念澄清

| 改动 | 说明 |
|------|------|
| `DramaRanking.weekly_heat_index` | 新字段，明确表示红果周热播指数 |
| `process_node` / `enrich_node` | 同步写入 `weekly_heat_index` |
| `assets/index.html` | 表格拆分「周热度」与「累计指数」；周榜坐标标注「周热播指数」 |

## 7. 演员热力榜纠偏（同日追加）

**现象：** 演员热力榜出现周迅、赵丽颖、杨幂、孙红雷、胡歌等**传统影视一线明星**，且男女榜分数呈 224→133 等模板递减；杨紫误入男频榜。

**根因链：**

1. `enrich_node` DeepSeek 补全主演时，将一线明星写入 `female_lead`/`male_lead`
2. `actor_ranking_node` 从榜单字段直接统计，未过滤非短剧演员
3. `config/actor_ranking_llm_cfg.json` 旧 prompt 要求「严禁填未知、从常见名单猜测」，周一不足 10 人时 DeepSeek **编造名单外演员**，popularity 固定 800–999

**修复：**

| 改动 | 说明 |
|------|------|
| `data_quality.py` | 新增 `MAINSTREAM_ACTOR_BLOCKLIST`、`GENERIC_ACTOR_NAMES`、`sanitize_actor_field` |
| `enrich_node.py` | 写入榜单前清洗一线明星/泛化假名 |
| `actor_ranking_node.py` | 移除 DeepSeek 凑数；提取时过滤不可信演员名 |
| `actor_ranking_llm_cfg.json` | 重写为「仅统计榜单内已有演员，禁止明星/假名」 |
| `quality_gate_node.py` | 演员有效性校验纳入一线明星过滤 |
| `metadata_fetcher.py` | **修复红果详情页 URL**（`/detail?series_id=`）+ HTML 演职员表解析 |
| `actor_resolver.py` | enrich 内红果 catalog 剧名匹配 `series_id`；Kimi 改为短剧垂类多轮 query |
| `enrich_llm_cfg.json` + `json_refiner.py` | DeepSeek 补全指令限定短剧演员示例，禁止明星/假名 |

**搜不到演员的真正原因（链路断裂点）：**

1. `latest.json` 中 TOP20 **全部 `series_id` 为空** → 红果详情爬虫从未触发
2. 旧 `metadata_fetcher` 使用错误 URL `/series/{id}`，页面结构已变，**即使有序列号也返回 None**
3. Kimi 批量搜索 query 过于泛化（「短剧信息查询」），未聚焦红果/DataEye 垂类来源
4. DeepSeek 在检索上下文薄弱时「猜」一线明星填坑

**更好数据源（已接入/建议）：**

| 优先级 | 来源 | 状态 |
|--------|------|------|
| P0 | 红果 `/detail?series_id=` 演职员表直爬 | ✅ 已修复 |
| P0 | 红果首页 catalog 剧名模糊匹配 `series_id` | ✅ enrich 内已接入 |
| P1 | Kimi 按剧搜索「短剧《剧名》主演 红果 DataEye」 | ✅ 已改 query |
| P2 | DataEye 剧目详情 API（不稳定） | 待评估 |
| P2 | 抖音/小红书演员词条 | 可作为 Kimi 搜索关键词补充 |

**预期：** 下次 CI 后演员榜仅展示榜单内真实短剧主演；人数不足 10 时宁缺毋滥，不再用明星凑数。

**版本标记：** v1.14.5
